# 目录与工作边界

确认日期：2026-10-02。两个目录分别承担开发与参赛支持，不互相复制整套文件。

## 开发：finance-playground

- WSL：`/home/stargazer/workspace/finance-playground`
- Windows：`\\wsl.localhost\Ubuntu-24.04\home\stargazer\workspace\finance-playground`
- GitHub：<https://github.com/Starxxgazer/finance-playground>
- 远端：`origin`；主分支：`main`。任务使用短期工作分支，完成后通过 PR 合并并清理分支。

| 位置 | 存放内容 |
| --- | --- |
| `AGENTS.md`、`README.md` | 开发规则与项目入口 |
| `.github/` | 项目自动检查与 PR 配置 |
| `docs/design/` | 游戏形式、玩法、故事候选与试玩反馈 |
| `docs/standards/` | 开发负责人确定的内容格式、接口与数值约定 |
| `docs/archive/` | 已放弃或被替代的历史产品方案 |
| `docs/协作指南.md` | 团队分工、分支及提交步骤 |

游戏体裁与技术方案尚未确定，暂不创建代码、资源、测试的占位结构；确定后由开发负责人补充。旧 Demo 不作为默认实现恢复。

本仓库提交前运行 `python3 .github/scripts/check_repository.py`，并人工检查实际暂存文件。忽略规则不能代替上传前的核对。

## 参赛支持：hackthon

- WSL：`/home/stargazer/workspace/hackthon`
- Windows：`\\wsl.localhost\Ubuntu-24.04\home\stargazer\workspace\hackthon`
- 仅在本机使用，不连接 GitHub，不保存另一份游戏开发树。

| 位置 | 存放内容 |
| --- | --- |
| `官方比赛资料/` | 用户指定的最新官方资料包及同一版本的可读展开文件 |
| `参赛问答/` | 赛事问题、基于资料的回答、来源与待确认事项 |
| `参赛准备/` | 参赛待办、现场安排与路演准备 |
| `提交材料/` | 最终演示视频、演示文稿及提交回执等本地交付文件 |

官方资料只保留一个当前版本；替换时先校验新包及附件，再删除旧版。问答以该版本为依据，区分官方原文、自己的解释与尚未确认的事项，不用已删除的旧问答补齐缺失信息。

`hackthon` 保留独立的本地 Git 边界且不设置远端，用于避免落入父级 workspace 仓库；该边界不用于游戏开发或云端同步。不要从父目录提交其中的资料。

## 两处之间如何协作

- 修改游戏、代码、产品设计与内容标准：进入 `finance-playground`。
- 查询赛题、提交要求、现场安排等参赛问题：进入 `hackthon`。
- 赛事要求影响产品时，只把核实后的必要约束用自己的话写进开发文档，标明来源和确认状态；不复制官方手册、图片、附件或私人问答。
- 准备提交时，将项目产出的最终文件导出到 `hackthon/提交材料/`；不把整个源码仓库复制过去，源代码仍以 GitHub 为准。
- 不建立指向官方资料的符号链接，不用同步工具将 `hackthon` 整体同步进开发仓库。
